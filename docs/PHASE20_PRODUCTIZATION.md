# Phase 20 产品化开发记录

## 20-1 价格变化订阅 MVP

首个可用渠道选择“浏览器本地通知”，保持静态架构且不收集个人信息。用户可按具体模型、标准模型（跨平台）、平台、免费状态、新模型、退役状态或降价阈值创建订阅，并选择检测到即通知或每日最多一次。

闭环包括：

- 订阅、退订与当前数据基线保存在浏览器 `localStorage`；
- 网站打开并加载新数据版本时，将当前目录与上次快照比较；
- 只有状态改变或达到降价阈值时才生成事件；
- 通过 Service Worker 调用浏览器通知渠道；
- 以事件 ID 去重，保存最近 100 条发送记录；
- 失败事件最多重试 3 次；
- 订阅创建、退订和成功发送进入不含个人信息的会话级产品漏斗事件。

边界：这是“访问时检测”的本地 MVP，不是后台常驻推送。浏览器必须允许通知，清除站点数据会删除订阅；当前版本不会上传订阅内容。后续只有在验证用户需求后，才增加邮件或服务器端 Web Push。

验收证据：Playwright 在桌面和 Pixel 7 视口验证订阅、发送记录和退订闭环；自动化使用注入式通知传输验证确定性业务流程，生产默认传输仍为浏览器 Notification/Service Worker API。真实用户是否收到通知取决于其浏览器和系统权限，不把自动化通过称为真实用户送达。

## 20-2 企业模型选型报告 MVP

报告完全在浏览器中按确定性规则生成，输入覆盖业务场景、日请求量、输入/输出 Token、上下文、延迟、视觉/工具/推理/代码能力、国内外平台范围、月预算和最低可信度。

- 只允许 `priced`/`free` 且按 Token 计费的模型进入成本计算；
- 未达到上下文、能力、区域或可信度要求的模型会被排除；
- 无价格证据链接的记录不会进入候选；
- 月成本统一按“日请求量 × 30 ×（输入 Token × 输入单价 + 输出 Token × 输出单价）”计算，美元使用当前数据版本汇率换算；
- 输出前 5 个候选、3 个备选的结构化数据、成本、可信度、上下文和证据链接；
- 严格延迟要求明确提示必须使用真实请求压测，认证前 TTFB 不作为生成延迟证据；
- 支持导出 Markdown 和 HTML 数据源。

Playwright 会从报告首个候选回溯到原始模型记录，独立重算月成本，并检查价格证据、数据更新时间、严格延迟风险和 Markdown 下载。测试通过代表计算与导出闭环，不代表企业客户已验收或愿意付费。
